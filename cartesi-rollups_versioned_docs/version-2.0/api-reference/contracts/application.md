The **Application** contract serves as the base layer representation of the application running on the execution layer. The application can interact with other smart contracts through the execution and validation of outputs. These outputs, generated by the application backend on the execution layer, can be proven in the base layer through claims accepted by a consensus contract.

Every Application is subscribed to an outputs Merkle root validator (usually a [consensus contract](./consensus/overview.md)), which accepts the claims used to validate outputs, and reads its inputs from an input box. Both are chosen at deployment. An Application may also have an owner, but the owner can only migrate the application to another outputs Merkle root validator **in the block in which the application was deployed**: in any later block, [`migrateToOutputsMerkleRootValidator()`](#migratetooutputsmerklerootvalidator) reverts with `NotDeploymentBlock`. This lets factories deploy an application and its consensus in a single transaction. Applications deployed through the [`SelfHostedApplicationFactory`](./application-factory.md#selfhostedapplicationfactory) are ownerless.

Consequently, users of an Application must trust its outputs Merkle root validator and its input box. Before depositing assets or relying on outputs, check [`getOutputsMerkleRootValidator()`](#getoutputsmerklerootvalidator) and [`getInputBox()`](#getinputbox). The input box in particular should be the canonical [`InputBox`](./input-box.md) deployment; see [Choosing and checking the input box](./input-box.md#choosing-and-checking-the-input-box). For more information about different ownership and consensus models, refer to the [consensus contracts](./consensus/overview.md).

An Application may optionally be deployed with a [`WithdrawalConfig`](./withdrawal/withdrawal-config.md) that turns on **foreclosure and emergency withdrawal**. A chosen **guardian** can foreclose the application. Once it is foreclosed, users can withdraw their in-app balances straight from this contract by proving their accounts against the last-finalized machine state, and deposits whose inputs were not finalized can be refunded to their depositors. See [Foreclosure & Emergency Withdrawal](../../development/emergency-withdrawal/overview.md) for the full flow. These functions are documented below under [Guardian & Foreclosure](#guardian--foreclosure), [Deposit Refunds](#deposit-refunds) and [Emergency Withdrawal](#emergency-withdrawal).

This contract inherits from `IApplication`, OpenZeppelin's `Ownable`, `ERC721Holder` and `ERC1155Holder` (so it can receive ERC-721 and ERC-1155 tokens), and `RollupsContract` (which implements `version()`).

### `executeOutput()`

```solidity
function executeOutput(bytes calldata output, OutputValidityProof calldata proof) external override
```

Execute an output. Only vouchers and DELEGATECALL vouchers are executable; notices can only be validated (see [`validateOutput()`](#validateoutput)).

The output is validated against a claim accepted by the current outputs Merkle root validator, so it can only be executed after a claim covering its epoch has been accepted (with `Authority` and `Quorum`, after the claim staging period).

*On a successful execution, emits an `OutputExecuted` event.*

The function follows the checks-effects-interactions pattern and has no reentrancy guard: it marks the output as executed, increments the executed outputs count and emits `OutputExecuted` **before** executing the output. A contract called by the output therefore already sees `wasOutputExecuted(outputIndex)` return `true`.

Foreclosure does not block this function: outputs validated against claims accepted before the foreclosure can still be executed.

**Parameters**

| Name | Type | Description |
|------|------|-------------|
| `output` | `bytes` | The output |
| `proof` | `OutputValidityProof` | The proof used to validate the output against a claim accepted to the current outputs Merkle root validator contract |

**Errors**

| Error | Condition |
|-------|-----------|
| `InvalidOutputHashesSiblingsArrayLength` | The proof's siblings array has an invalid length |
| `InvalidOutputsMerkleRoot(bytes32)` | The outputs Merkle root computed from the proof is not valid according to the current outputs Merkle root validator |
| `OutputNotReexecutable(bytes)` | The output was already executed |
| `OutputNotExecutable(bytes)` | The output is not a voucher or a DELEGATECALL voucher (for example, a notice) |
| `InsufficientFunds(uint256 value, uint256 balance)` | The application does not have enough Ether for the voucher's `value` |
| `TargetHasNoCode(address)` | The voucher has a non-empty payload, or the output is a DELEGATECALL voucher, and the destination has no code |

If the call made by the output reverts, its error data is propagated.

## Guardian & Foreclosure

These members are part of `IApplication` (until rollups-contracts 3.0.0-alpha.6 they were in a separate `IApplicationForeclosure` interface). They are only meaningful when the application was deployed with a non-empty [`WithdrawalConfig`](./withdrawal/withdrawal-config.md); the guardian is the address set in that configuration.

### `foreclose()`

```solidity
function foreclose() external override onlyGuardian notForeclosed
```

Forecloses the application, allowing users to withdraw their funds by providing Merkle proofs of their in-app accounts, and to recover deposits whose inputs were not finalized.

*Can only be called by the application guardian. On success, emits a `Foreclosure` event. An application that has been foreclosed remains so, and the `Foreclosure` event is emitted at most once.*

After foreclosure:

- The `InputBox` rejects new inputs for the application with `ApplicationForeclosed`.
- `Authority` and `Quorum` reject claim submission, staging and acceptance for the application with `ApplicationForeclosed`.
- `migrateToOutputsMerkleRootValidator()` reverts with `Foreclosed`.
- `issueRefund()`, `proveAccountsDriveMerkleRoot()` and `withdraw()` become available.

**Errors**

| Error | Condition |
|-------|-----------|
| `NotGuardian` | Called by an account other than the guardian |
| `Foreclosed` | The application was already foreclosed |

Get the address of the guardian, which has the power to foreclose the application.

## Deposit Refunds

After foreclosure, deposits made through the canonical portals whose inputs were not finalized can be returned to their original depositors. An input is finalized when the outputs Merkle root validator reports it so through [`wasInputFinalized()`](./consensus/ioutputs-merkle-root-validator.md#wasinputfinalized). For `Authority` and `Quorum`, that means the input was added in a block covered by an accepted claim.

Refunds are built by the refund output builder (see [`getRefundOutputBuilder()`](#getrefundoutputbuilder)), which supports Ether, ERC-20, ERC-721, and single and batch ERC-1155 deposits made through the portals it knows. The refund is not automatic: anyone must call `issueRefund()` for each input.

### `issueRefund()`

```solidity
function issueRefund(uint256 inputIndex, bytes calldata input) external override onlyForeclosed
```

Issue a refund for a deposit input that was not finalized. Callable by anyone once the application is foreclosed. The asset is returned to the original depositor, whoever calls the function.

The function validates the input against the application's input box, checks that it was not finalized, builds the refund output with the refund output builder, and executes it.

*On success, marks the input as refunded, increments the issued refunds count and emits a `RefundIssued` event. Like `executeOutput()`, it follows the checks-effects-interactions pattern: the input is marked as refunded and the event is emitted **before** the refund output is executed.*

**Parameters**

| Name | Type | Description |
|------|------|-------------|
| `inputIndex` | `uint256` | The index of the input in the application's input box |
| `input` | `bytes` | The input that was sent to the application, as emitted in the `InputAdded` event (the ABI-encoded `EvmAdvance` call) |

**Errors**

| Error | Condition |
|-------|-----------|
| `NotForeclosed` | The application has not been foreclosed |
| `RefundAlreadyIssued(uint256 inputIndex)` | A refund was already issued for this input |
| `InvalidInputIndex`, `InvalidInputHash`, `IllFormedInput` | The input does not match the input box (see [`validateInput()`](#validateinput)) |
| `CannotRefundFinalizedInput(uint256 inputIndex)` | The input was finalized |
| `UnknownInputSender(address inputSender)` | The input was not sent by a portal known to the refund output builder (for example, a non-deposit input) |
| `OutputNotExecutable`, `InsufficientFunds`, `TargetHasNoCode` | The refund output could not be executed |

If the asset transfer reverts (for example, a depositor contract that does not accept the asset), its error data is propagated.

## Emergency Withdrawal

These members are part of `IApplication` (until rollups-contracts 3.0.0-alpha.6 they were in a separate `IApplicationWithdrawal` interface). After the application is foreclosed, its **accounts drive** (the in-app balance ledger) is proved on-chain once, and then each account's funds can be withdrawn permissionlessly. For the end-to-end procedure see the [recovery guide](../../development/emergency-withdrawal/recovery-guide.md); for the output-building contracts see the [Withdrawal](./withdrawal/overview.md) subsection.

Withdrawal-related functions take an `AccountValidityProof`:

```solidity
struct AccountValidityProof {
    uint64 accountIndex;      // the account's index in the accounts drive
    bytes32[] accountRootSiblings; // Merkle siblings of the account root
}
```

### `proveAccountsDriveMerkleRoot()`

```solidity
function proveAccountsDriveMerkleRoot(
    bytes32 accountsDriveMerkleRoot,
    bytes32[] calldata proof
) external override onlyForeclosed
```

Prove the accounts drive Merkle root against the last-finalized machine Merkle root provided by the application's outputs Merkle root validator. If no machine Merkle root has been finalized yet (the validator returns zero), the application's template hash is used instead. Callable by anyone after the application is foreclosed, so that accounts can be validated and their funds withdrawn. The root can only be proved once.

*On success, stores the proved accounts drive Merkle root and emits an `AccountsDriveMerkleRootProved` event.*

**Parameters**

| Name | Type | Description |
|------|------|-------------|
| `accountsDriveMerkleRoot` | `bytes32` | The accounts drive Merkle root |
| `proof` | `bytes32[]` | Siblings of the accounts drive Merkle root in the machine state tree |

**Errors**

| Error | Condition |
|-------|-----------|
| `NotForeclosed` | The application has not been foreclosed |
| `AccountsDriveMerkleRootAlreadyProved` | The root has already been proved |
| `InvalidAccountsDriveMerkleRootProofSize` | The proof array length is wrong |
| `InvalidMachineMerkleRoot(bytes32)` | The computed machine root differs from the last-finalized one, or from the template hash if none was finalized (argument is the computed root) |

### `withdraw()`

```solidity
function withdraw(bytes calldata account, AccountValidityProof calldata proof) external override onlyForeclosed
```

Withdraw the funds of an account from the foreclosed application. First the account is validated against the proved accounts drive Merkle root; then a withdrawal output is built from the account and executed.

*On success, marks the account funds as withdrawn, increments the withdrawals count and emits a `Withdrawal` event. Like `executeOutput()`, it follows the checks-effects-interactions pattern: the account is marked as withdrawn and the event is emitted **before** the withdrawal output is executed.*

**Parameters**

| Name | Type | Description |
|------|------|-------------|
| `account` | `bytes` | The account, as encoded in the accounts drive |
| `proof` | `AccountValidityProof` | The proof used to validate the account |

**Errors**

| Error | Condition |
|-------|-----------|
| `NotForeclosed` | The application has not been foreclosed |
| Errors from `validateAccount()` | The account fails validation (see [`validateAccount()`](#validateaccount)) |
| `AccountFundsAlreadyWithdrawn(uint64)` | The account's funds were already withdrawn (argument is the account index) |
| Errors from the withdrawal output builder | For example `InvalidAccountSize(uint256 attemptedAccountSize, uint64 accountSize)` (see [`IWithdrawalOutputBuilder`](./withdrawal/iwithdrawal-output-builder.md)) |
| `OutputNotExecutable`, `InsufficientFunds`, `TargetHasNoCode` | The withdrawal output could not be executed |

### `getAccountsDriveStartIndex()`

```solidity
function getAccountsDriveStartIndex() public view override returns (uint64)
```

Get the start-index factor of the accounts drive. With `a = getLog2LeavesPerAccount()`, `b = getLog2MaxNumOfAccounts()`, and `c = getAccountsDriveStartIndex()`, the accounts drive starts at memory address `c * 2^(a+b+5)` and is `2^(a+b+5)` bytes in size.

### `getWithdrawalOutputBuilder()`

Get the [withdrawal output builder](./withdrawal/iwithdrawal-output-builder.md), which is static-called whenever an account's funds are to be withdrawn.

### `validateAccount()`

```solidity
function validateAccount(bytes calldata account, AccountValidityProof calldata proof) public view override
```

Validate the existence of an account at a given index in the accounts drive, against the accounts drive Merkle root proved through `proveAccountsDriveMerkleRoot()`.

*May raise any error raised by [`validateAccountMerkleRoot()`](#validateaccountmerkleroot), as well as `DriveSmallerThanData` (if the provided account is too large).*

### `validateAccountMerkleRoot()`

```solidity
function validateAccountMerkleRoot(bytes32 accountMerkleRoot, AccountValidityProof calldata proof) public view override
```

Validate the existence of an account root at a given index in the accounts drive.

**Errors**

| Error | Condition |
|-------|-----------|
| `InvalidAccountRootSiblingsArrayLength` | The siblings array length is wrong |
| `InvalidNodeIndex(uint256 nodeIndex, uint256 height)` | The account index is outside the accounts drive |
| `AccountsDriveMerkleRootNotProved` | The accounts drive root has not been proved yet |
| `InvalidAccountsDriveMerkleRoot(bytes32)` | The computed accounts drive root differs from the proved one (argument is the computed root) |
